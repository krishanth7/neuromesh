# ADR 0003: Mutual TLS and session-bound application identities

Status: implemented experimental transport library.

Quinn provides QUIC over UDP; Rustls provides TLS 1.3. Operators supply certificate
chains, private keys, explicit trust roots, and an application NodeId allowlist.
Both endpoints must present a valid certificate. Clients verify the DNS name.
No custom certificate verifier or verification bypass exists. ALPN is `nmp/1`.
0-RTT application traffic is disabled.

The first bidirectional stream exchanges 96-byte proofs (32-byte Ed25519 public
key and 64-byte signature). Each signature covers the ASCII context
`NeuroMesh identity proof v1`, a role byte (initiator 0, responder 1), and 32 bytes
from TLS exporter label `EXPORTER-NeuroMesh-identity-v1`, context `nmp/1`.
This binds the application proof to a TLS session and prevents reflection between
roles. The key fingerprint must be allowlisted; the initiator additionally checks
the exact expected NodeId. A certificate alone does not authorize an application
identity. There is currently no configured one-to-one certificate/NodeId mapping.

After authentication, each stream carries one length-prefixed NMP request and
response. Request IDs increase, response IDs match, and sender IDs must match the
authenticated identity. Only the connection initiator sends requests; establish a
separate reverse connection if needed. At most one application operation per
session is admitted; concurrent calls fail instead of accumulating a queue.
Atomic sequence state is protected by this admission rule, with no state mutex
held across I/O. A handler is synchronous and must be fast/nonblocking; this API
is for bounded control messages, not arbitrary user code or compute workloads.

## Limits

- 1–1024 connections per endpoint, including admitted handshakes.
- At most that many buffered incoming attempts; 64 KiB per attempt and a total
  of connection-cap × 64 KiB. This is bounded but is not Internet DoS protection.
- One bidirectional stream, zero unidirectional streams per connection.
- 64 KiB NMP frames, checked before allocation; trailing bytes rejected.
- 64 KiB + 4 stream receive window; 128 KiB connection receive/send windows.
- Five-second TLS, proof, and operation deadlines; 15-second QUIC idle timeout.
- Session drop closes its connection and releases admission capacity.

A response waits for QUIC delivery acknowledgement before returning. This is not
proof of application processing. A timed-out/invalid exchange closes the session.
Accepted sessions waiting for a request also have a five-second deadline; callers
must design heartbeat cadence accordingly. Endpoint accept itself waits until a
connection arrives or the endpoint closes.

## Validation and remaining work

Real localhost tests cover authenticated pings, certificate/hostname rejection,
unknown/wrong expected identities, capacity exhaustion/release, and shutdown.
Unit tests reject proof reuse across TLS bindings and roles. Certificates in tests
are ephemeral fixtures, never production keys. No discovery, peer registry, mesh
runtime, traffic forwarding, task execution, or external security audit is claimed.
